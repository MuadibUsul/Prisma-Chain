# CanonicalMathV1 — fixed-point numeric design

Status: FROZEN. Every nonlinear operator of the Transformer block uses this
single numeric contract; changing it requires a new version
(`CANONICAL_MATH_V2`) and cannot silently alter an existing operator.

Data: `docs/canonical-math-v1-analysis.json` (generated by
`tools/canonical_math_analysis.py`, fixed seeds 7/11/13 plus adversarial
vectors; float64 is the reference only and never appears in the protocol
path).

## Chosen format

**Q12.20 in a signed int32**: 20 fractional bits, range [-2048, 2048),
resolution 2^-20 ≈ 9.54e-07. All canonical tensors of activation type use
it; GEMM_INT8_V1 keeps its frozen int8/int32 wire format and converts
through REQUANTIZE_V1.

Why not the alternatives (measured, see JSON):

| format | range | resolution | RMSNorm max abs err | softmax worst cosine | verdict |
| --- | --- | --- | --- | --- | --- |
| Q16.16 | ±32768 | 1.53e-05 | 3.5e-02 | 0.997 | 100x coarser below 2048; RMSNorm error too high |
| **Q12.20** | **±2048** | **9.54e-07** | **8.2e-04** | **0.997** | chosen |
| Q8.24 | ±128 | 5.96e-08 | 1.2e-05 | 0.30 (range overflow) | cannot represent logits (beyond ±128) |

## Arithmetic contract

- Addition/subtraction: int32 with saturating clamp into the Q12.20 range.
- Multiplication: 64-bit product, round-to-nearest **ties-to-even** shift
  back by 20 bits (the only rounding mode of the protocol).
- Division: round-to-nearest ties-to-even on `(a << 20) / b`; division by
  zero is a spec violation (rejected, never defined).
- Saturation: clamping to [-2^31, 2^31-1] is protocol semantics where a
  spec says so (REQUANTIZE_V1, canonical_exp above 21); never silent
  wraparound.
- No libm, no floats, no FP16/BF16/FP32 anywhere in canonical semantics.

## Canonical functions (algorithms frozen here)

- **invsqrt(x)**: normalize x = m·4^e with m∈[1,4); a pinned 16-point table
  of 1/√m (Q12.20, generated once by high-precision math and committed)
  provides a ≤9% estimate; apply the 4^-e scale to the estimate BEFORE
  iterating; exactly 3 Newton steps at doubled internal precision (all
  int64-safe); result saturates, never diverges. Measured relative error ≤ 1e-3
  at the very top of the Q12.20 range (2047) and ~4e-5 elsewhere;
  the numeric-design simulation is the measured RMSNorm end-to-end
  bound in docs/canonical-math-v1-analysis.json.
- **exp(x)**: 2^(x/ln2) with floor split into integer power and a cubic on
  f∈[0,ln2) with pinned coefficients (ln2, ln2²/2, ln2³/6 rounded to
  Q12.20); x ≤ -24 underflows to 0, x ≥ 21 saturates at the Q12.20 max.
- **sigmoid(x)** (SiLU): two-branch stable form; 1/(1+e^-x) for x ≥ 0 and
  e^x/(1+e^x) for x < 0, so the exponent is always non-positive.
- **softmax row**: subtract the row max (mandatory), canonical exp,
  canonical sum, then per-element exact division; no other normalization
  order is canonical.
- **sin/cos for RoPE**: a pinned table sin/cos(position, frequency) in
  Q12.20 for the committed maximum sequence length, generated once by
  high-precision math; runtime never calls libm.

## Predeclared acceptance thresholds (fixed before block benchmarks)

These were written down before any transformer-block benchmark ran and are
not adjusted afterwards. A failure forces a `CANONICAL_MATH_V2` spec
change, never a silent algorithm swap.

| scope | metric | threshold |
| --- | --- | --- |
| RMSNorm | max abs error vs float64 ref | ≤ 5e-3 |
| RMSNorm | min cosine similarity | ≥ 0.9999 |
| SiLU | max abs error for \|x\|≤1 | ≤ 5e-3 |
| SiLU | max relative error for \|x\|>1 | ≤ 1e-2 |
| Softmax | max abs error | ≤ 5e-2 |
| Softmax | min cosine similarity | ≥ 0.99 |
| RoPE | max abs error | ≤ 1e-4 |
| ADD / MUL / REQUANTIZE | max abs error | 0 (exact integer ops) |
| full block vs float64 reference | min cosine similarity | ≥ 0.995 |
| full block vs float64 reference | max abs error | ≤ 5e-2 |

Measured worst cases under these thresholds (Q12.20): RMSNorm 8.2e-4,
SiLU 4.4e-2 absolute at \|x\|≈12 (relative ≈3.7e-3, within the relative
criterion), softmax 3.6e-2 / cosine 0.997, RoPE 4.7e-6. The unit of
"activation tensor" everywhere below is Q12.20 int32, row-major.
