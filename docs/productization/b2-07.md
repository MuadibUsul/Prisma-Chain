## 1. What is built

A line-by-line mirror of the frozen construction
(`tools/f5c_commit_v3.py` + `compute/canonical/python/canonical_ref.py`):

| element | construction |
|---|---|
| TensorRootV2 node leaves | `hash(DOMAIN_MANIFEST_V2, graph_id, u32be(node_id), operator_id, operator_version, encode_canonical(output))`, then `hash(leaf, root_bytes)` |
| ManifestV2 | pairwise Merkle over the leaves, the last node duplicated on odd levels |
| GraphResultCommitV3 | protocol_version `3.0.0`, frozen arithmetic `A13W10_I64_PROFILE_V1` and PolicyID, task/assignment refs, worker pubkey, manifest root, final output root |
| signature | ed25519 over `DOMAIN_SIG_V3 ‖ encode_canonical(wire view)` with the signature field cleared to `b""` — `identity.sign_raw` adds **no framing**, exactly the frozen preimage |
| final_output_root | `hash(DOMAIN_VWR, last_root)` |
| task/assignment binding | `verify_binding` refuses a commit whose task ref, assignment ref or worker key differs |
| duplicate-submit protection | journal-first guard: no journal entry or a non-accepted phase refuses; a `submitted` phase refuses a second commit; the commit id (preimage hash) is recorded |

`jobs commit` builds, signs, binds and guards a commit from a verified
profile + node roots, writing the artifact B2-08 will upload.

## 2. Evidence

**Byte-for-byte vs the frozen tool** (test): the unsigned object *and* the
signature are identical to `f5c_commit_v3.build_signed_commit_v3` for the
real 310-node frozen graph with the same key and inputs.

**Independent cross-language verifier** (the roadmap's requirement): the
produced commit is handed to the repository's Go verifier
(`go run ./tools/f5c_verify_commit`), which decodes it with the **chain's own
encoder** and calls `canonical.VerifyGraphResultCommitV3Signature` →
`COMMIT OK`. A tampered commit (one field changed after signing) is rejected
by the same verifier. CI now installs a Go toolchain in the worker job so
this gate runs there too, not only locally.

**Tests**: `pytest -q worker/tests` — **101 passed, 1 skipped** (10 new):
manifest equality, object+signature equality, preimage covers the cleared
signature field and changes with any field, Go verifier accept/reject,
binding refusals (task / assignment / worker), commit-id stability across
signing, duplicate submission impossible, commit-before-accept refused,
malformed inputs refused.

**Bug found while writing the tests**: the duplicate guard accepted a task
with *no* journal entry (it only checked the phase when an entry existed) —
fixed so a commit cannot be built for a task that was never accepted.

## 3. Scope note

The **submit-result chain transaction** is not wired here: the frozen chain
accepts a commit only for a real accepted V2 graph task, and a real
execution is blocked on the GPU gate (B2-06, SM86/SM89). Everything up to
the transaction — build, sign, bind, self-check, independent verification,
duplicate protection, artifact output — is done and tested, and B2-08
consumes the same artifact for the DA upload.

## 4. Definition of Done check

```text
commits verify under the independent cross-language verifier   yes — Go verifier
    (chain encoder) accepts; tampering is rejected
duplicate submission impossible                                yes — journal guard,
    tested both directions (second submit refused, unaccepted task refused)
```

## 5. Carried into later tasks

1. B2-08 uploads the signed commit's bundle to the DA providers and
   submits refs; the commit id in the journal is the idempotency key.
2. The live submit-result transaction runs with the first real execution
   (GPU_REAL_SMOKE, B2-06/09); its wiring is the only remaining half of the
   commit path and is not claimed as done.
3. `completed_epoch` must come from the chain, not the local clock — the
   Phase D/E experience (receipt rebuild with the worker's declared
   completed_epoch) is encoded in the required `--epoch` argument.
