## 1. Metadata policy (B1-01a)

| decision | value | notes |
|---|---|---|
| binary name | `prismad` | chain node; `prisma-vm` continues unchanged |
| software version | `git describe --tags --match 'v*' --always` | source of truth is repo state; at this commit: `v0.1.1-phase0-114-gf827792`. When the product line tags its own releases, describe picks the new tag up automatically. |
| git SHA | full SHA stamped via `-ldflags -X prismachain/chain/version.gitCommit` | comes from `git rev-parse HEAD` at build time |
| protocol version | generated into `chain/version/protocol_gen.go` from `docs/phase-f-freeze.json` by `chain/tools/genprotocolversion` | **never hand-typed**; `TestGeneratedMatchesFreezeArtifact` re-reads the artifact and fails on drift; `TestFrozenIdentityConstants` pins the frozen literals |
| build date | **none embedded** | policy: no wall-clock timestamp enters the binary hash; the git commit is the timestamp authority (roadmap allows "SOURCE_DATE_EPOCH-style or omit") |
| VCS stamping | `-buildvcs=false` | disables Go's default VCS stamping so the hash is a pure function of source + toolchain + flags |
| release flags | `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 -trimpath -buildvcs=false` | same flags in `scripts/repro_build.sh` and `chain/Dockerfile` |

`prismad version [--json]` prints: software version, git commit, build
target, protocol phase, freeze tag, freeze commit, graph protocol,
GraphIDV2, PolicyID and all nine frozen component versions. It performs no
config reads and creates no files (verified: zero files created with a
fresh `HOME`). It **replaces** the SDK's generic `version` command so
`prismad version` is unambiguously the Prisma identity.

`prismad health [--rpc URL] [--timeout D]` queries the node's RPC
`/status` with a bounded timeout (default 3 s), prints
`ok chain_id=… height=… catching_up=…` and exits 0; any failure exits 1
with a reason on stderr. A node that is still catching up is healthy
(liveness), so `catching_up` is reported but not enforced.
