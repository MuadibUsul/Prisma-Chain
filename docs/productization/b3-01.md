## 1. What is packaged

```text
prisma-watcher init    challenger identity (B2-01 rules) + config
prisma-watcher run     discover -> retrieve -> verify -> journal (bounded loop)
prisma-watcher status  journal summary (phases, verdicts)
prisma-watcher verify  one-off verification of a downloaded bundle
```

Pipeline (per completed task), layered so everything is injectable and
testable without a network:

```text
discover      bounded per-task scan (chain_scan.py: the frozen chain has per-task
              queries; statuses result_submitted/challenged/... count as work)
retrieve      HttpBundleSource over the B4-01 DA surface (GET /v1/da/{task}/output),
              provider fail-over, task-id check, size bound
verify        the frozen WatcherV2 — root phase (artifact/version/GraphIDV2/roots/
              manifest/final), Freivalds (detection only) and the cheap exact
              recomputations; loaded from the frozen tree, never re-implemented
report        conservative verdict mapping: fraud/fail -> fraud, pass/clean ->
              clean, anything else -> unknown (the full report is journaled)
journal       per-task phase entries; a restart resumes discovered/retrieved
              tasks instead of re-verifying everything
```

**Detection is detection-only**: a fraud verdict is recorded and journaled;
the challenge transaction is B3-02's job, and slashing is always the chain's
deterministic adjudication — never a probabilistic trigger.

## 2. Evidence

`pytest -q watcher/tests` — **12 passed**:

- daemon lifecycle (9): verify + journal, verified tasks are never
  reprocessed, retrieval failure journaled and resumed on the next pass,
  bounded scheduler, pending-task recovery, frozen libraries located, HTTP
  source round-trip, provider fail-over + size bound, chain-scan statuses;
- **real frozen WatcherV2 runs (3)**: the honest + GEMM-fraud bundle pair was
  produced with the frozen tool (`tools/f5c_real_fraud.py --kind gemm --node
  145`), and the watcher's FrozenVerifier maps the honest run to `clean` and
  the fraud/tampered runs to `fraud` — the known fraud artifact is detected
  by the packaged watcher, end to end.

CI installs the watcher package and runs its tests.
