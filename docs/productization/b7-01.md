## 1. Policy enforced

```text
address validation   bech32 + `prsm` prefix + 20-byte account payload (the worker's
                     validated decoder — no second implementation)
per-account cooldown  a funded address waits the configured window (default 1h)
per-IP rate limit     token bucket (burst + refill), 429-style refusal
anti-loop            an IP funding more than N distinct addresses inside the window is
                     refused (bounded, documented)
balance monitoring   every request checks the faucet balance and logs an ALERT under
                     the threshold
metrics              requests / funded / cooldown_refused / rate_limited /
                     farming_refused / invalid_address
```

Every successful response carries and the README states plainly:
**test tokens have no monetary value.**

## 2. Evidence

`pytest -q faucet/tests` — **8 passed**: prefix/length/checksum validation (the
prismad-derived address vector passes), per-address cooldown (refused inside,
allowed exactly after the window), per-IP burst exhaustion and refill recovery,
anti-loop (the 4th distinct address from one IP refused; old window entries
expire), the no-value notice on every response, low-balance alerting, and the
outcome metrics.

**Bug the tests caught and fixed**: the per-IP token bucket handed the first
request a free token (a fresh bucket returned True without consuming) — the
first request now consumes from the burst like every other.
