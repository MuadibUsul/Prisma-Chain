## 1. What is packaged

```text
prisma-da init       provider identity (same rules as B2-01: encrypted keystore,
                     0600, passphrase via stdin/env/prompt) + config file
prisma-da register   registration transaction (`compute register-da-provider`) from a
                     temporary 0700 keyring that is shredded immediately afterwards
prisma-da run        serve the DA surface (restart recovery runs at start-up)
prisma-da status     local index + configuration summary
```

HTTP surface (routing is a pure function, so the whole surface is unit-testable
without sockets):

```text
GET  /health                    provider, protocol version, advertised key, stored tasks, uptime
GET  /metrics                   request/store/attest/retrieval counters + index metrics
POST /store                     verify (frozen root recomputation) then persist atomically
POST /attest                    canonical signed DAAttestation in the Go-shaped wire form
GET  /v1/da/{task}/output       canonical blob (hex), content hash re-verified before serving
GET  /v1/da/{task}/tile/{i}/{j} 501 — typed chunk proofs land with B4-02
```

Frozen formats are **loaded** from the frozen Python libraries
(`compute/canonical/python`, `compute/gemmv1/python`) via
`prisma_da.frozen`: the attestation preimage, tile encoding and Merkle
construction are never re-implemented. When they are not in a repository
checkout, `PRISMA_FROZEN_PYTHON` points at them and a missing library is an
explicit error naming what is missing.

Storage invariants (the reason the chain can trust a provider):

- **verify before storing** — the root is recomputed from the received bytes;
  `OUTPUT_ROOT_MISMATCH` refuses to store *or* attest;
- **atomic publish** — staged in `.incoming`, fsynced, then renamed: a crash
  never leaves a half artifact that looks complete;
- **verify on read** — every served byte is re-hashed; a mismatch quarantines
  the artifact (`quarantine-<task>-<stamp>/` + `quarantine.reason`) and refuses
  to serve it;
- **restart recovery** — `rescan()` rebuilds the index from disk at start-up
  and quarantines anything that no longer verifies.

Graceful shutdown stops accepting, drains in-flight requests (bounded), then
exits — writes are never cut in half (and the storage layer is atomic anyway).

## 2. Evidence

**Live cross-package smoke — 5/5 PASS** (`deploy/da_smoke.py`; results in
`docs/productization/b4-01-da-smoke.json`): three real `prisma-da run`
processes on real ports, driven by the **worker's** DA client (B2-08):

```text
PASS  three daemons serve /health
PASS  upload + verified attestations: 3 verified (signatures over the frozen
      preimage, checked by prisma_worker.da with the mirrored canonical encoder)
PASS  retrieval from all three: identical bytes
PASS  1/3 offline drill: quorum 2 still reached
PASS  2/3 offline drill: QuorumNotReached (explicit, with per-provider outcomes)
```

**Unit tests**: `pytest -q da/tests` — 12 passed; `pytest -q worker/tests` — 132
passed, 1 skipped. Coverage includes store/refuse paths, attestation verified by
the *worker's* verifier (cross-package), read-path and start-up-rescan
quarantine, metrics, the 501 tile route, and a real-socket HTTP + graceful
shutdown test.

**Bug the live smoke caught**: the worker's `/store` payload was missing the
`task_id32` field the provider needs to key its tile leaves — fixed in
`prisma_worker.da.store_bundle`/`ensure_quorum` (and pinned by the tests).

## 3. Definition of Done check

```text
a DA daemon can be installed, registered, serve uploads/retrievals and survive restarts   yes
     — install/register/run/status; live upload+retrieval; restart recovery rescans and serves
the surface the worker needs (B2-08) is stable    yes — proven by the live cross-package smoke
the surface the watcher needs (B3)                partial by design: tile proofs are B4-02
```
