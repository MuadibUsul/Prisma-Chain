```text
Task ID     B1-03
Status      DONE (2026-10-05)
Branch      product/testnet-alpha
Tool        chain/tools/netconfig (Go, same module as the chain)
Goal        one command produces a complete, checksummed, validated
```

Every result below comes from real runs on 2026-10-05 (commands + observed
output); the frozen parameters are imported from the chain code, never
retyped.

## 1. Tool surface

```text
netconfig newseeds --count N
netconfig generate  --spec spec.json --out DIR [--keep-homes DIR]
netconfig verify    --dir DIR [--prismad path]
netconfig provision --spec spec.json --bundle DIR --moniker M --home DIR
```

The spec (JSON) carries the chain-id, genesis time, denom, validators
(moniker, **seed**, p2p external address, funding, self-delegation), the
faucet test parameters and the RPC/P2P listen policy. Seeds never leave
the spec: artifacts contain public keys only.

Bundle output (documented location `network-config/<chain-id>/`, gitignored
because it is regenerable — the spec, not the bundle, is the source of
truth):

```text
chain-id.txt      network identifier
genesis.json      normalized: fixed genesis time, gentxs sorted, deterministic bytes
params.json       frozen protocol parameters, derived from the chain code + policy
validators.json   public identities: node id, account address, consensus pubkey
README.md         deterministic usage/verification text
manifest.json     sha256 + size of every file above
```

## 2. Rule compliance

| rule | implementation |
|---|---|
| B1-03a chain-id | `prisma-<network>-<generation>` (`^prisma-[a-z0-9]+-[0-9]+$`); devnet ids `prisma-mv-*`, `prisma-local-*`, `prisma-b1smoke-*` are **rejected** |
| B1-03b genesis | produced by the real toolchain (`prismad init --default-denom uprsm`, `genesis add-genesis-account/gentx/collect-gentxs`), not copied from the devnet; policy applied and asserted: every denom-bearing field must be `uprsm`, and the token `"stake"` anywhere in genesis is a hard error; mint inflation forced to zero (testnet issuance disabled until the audited base-task schedule exists) |
| B1-03c validator seeds | spec carries base64 seeds (>= 16 bytes); keys derived deterministically with versioned domain separation through the libraries' own derivations (`prisma/netconfig/v1/{consensus-key,node-key,account-key}:` + sha256, then cometbft ed25519 / SDK secp256k1 `GenPrivKeyFromSecret`); artifacts record node id, account address, consensus pubkey/address — **public only** |
| B1-03d RPC defaults | `rpc.laddr` must be set and must not contain `0.0.0.0` (rejected at spec validation and re-checked at bundle verification); the public exposure profile is B1-02's scope |
| B1-03e DA defaults | `DAWindowBlocks=30`, `DAChallengeBlocks=20`, `DAPenaltyUprsm=100000` — imported from `chain/x/compute` (which re-exports `compute/gemmv1`) |
| B1-03f challenge windows | `MinBond=1_000_000`, `ChallengeBlocks=20`, `ChallengeRoundBlocks=5`, `MaxQueuedChallenges=8`, `LightTokenPriceUprsm=1000`, graph bounds (1 MiB JSON, 512 nodes, 256 inputs, 512 evidence chunks, 64 outputs, bond multiple 16) — imported from the chain code; `checkParamsDrift` re-derives them at verify time so a bundle cannot silently drift from the frozen constants; gentx self-delegation must be >= `MinBond` |
| B1-03g faucet test params | amount / cooldown / per-address cap in the spec (validated: amount>0, cooldown>0, cap>=amount), recorded in `params.json`; test tokens only, no monetary claims |
| B1-03h checksum manifest | sha256 + byte size of every bundle file; `verify` hard-fails on mismatch and on any unlisted file |
| B1-03i config validation | `verify` runs all policy checks plus the SDK-level `prismad genesis validate`; `provision` re-validates the generated node home |

Explicitly recorded deviation: the **DA quorum** is not a named constant —
it is the literal `len(attesters) == 2` in `chain/x/compute/keeper.go` and
`gemm_receipt.go`. It is therefore recorded as a rule (`da_quorum_rule`)
with its source locations instead of a parameter, and B1-03's verification
does not pretend it is configurable.

## 4. Notes for later tasks

1. `--keep-homes DIR` deliberately writes private keys to an explicit path
   (bootstrap/Phase C convenience); the default bundle never contains them.
2. A 1-validator network has 100% voting power: appropriate for smoke and
   bootstrap, not for the private testnet topology (Phase C: 4 validators
   per the roadmap).
3. `network-config/` is gitignored on purpose: bundles are regenerated from
   the spec; specs (and seeds) stay with the operator.
4. B1-02 builds the public RPC/sentry profile on top of the generated node
   config; the generator already refuses to emit a wildcard RPC laddr.
