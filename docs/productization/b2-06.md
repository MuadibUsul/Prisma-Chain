## 1. Contract (what is frozen in code)

- **The GPU is not a consensus identity.** Consensus is over canonical
  tensor roots and the frozen arithmetic; the GPU is an accelerator whose
  outputs must match the frozen reference bit-for-bit. A worker on another
  *proven* device must produce identical roots. (Stated here because the
  roadmap requires it in the product docs.)
- **No silent fallback, no float path, no approximation.** Every failure is
  typed: `BackendUnavailable`, `UnsupportedShapeError`, `OutOfMemoryError`,
  `DeviceError`, `DeterminismError`, with `map_backend_exception` translating
  backend/SDK exceptions (OOM, CUDA, unsupported shape) without torch
  installed.
- **`select_backend` is the only supported way to obtain a backend.** It
  takes the B2-02 capability report: a proven capability (SM86/SM89) plus the
  frozen kernel sources yields `FusedMMA13W10Backend`; anything else is a
  refusal naming the reason; the deterministic `TestBackend` requires an
  explicit `--allow-test-backend` flag and is marked `is_reference = False`.

## 2. What is implemented vs blocked

```text
IMPLEMENTED (this host)
  backend selection contract + typed refusals
  deterministic TestBackend (domain-separated hashes, no torch, no floats)
     - drives the journal/commit plumbing and CI before any GPU exists
     - refuses the bit-exactness gate by design
  error taxonomy + exception mapping (OOM / device / unsupported)
  metrics: node count, per-op counts, wall time, memory high-water slot, errors
  determinism self-check hook (run twice, byte-compare) and the bit-exact
     comparison gate (compare_with_reference: any difference is a hard error)
  the frozen backend loader: kernel sources are read from the frozen tree
     (gpu/f5b1, gpu/f5b2) and compiled through torch's inline extension — the
     arithmetic is never re-implemented

BLOCKED (external hardware)
  GPU_REAL_SMOKE: bit-exact execution of the 310-node block vs the frozen
     reference on SM86/SM89, the operator/vector gates and the product gate.
     This host is an RTX 2060 SUPER (SM75 < SM86), so the gate cannot run
     here and is NOT claimed. Per the standing rule: no fake PASS.
```

## 3. Evidence

`pytest -q worker/tests` — **91 passed, 1 skipped** (14 new): selection
matrix (proven capability selects the frozen backend; a proven capability
without kernel sources refuses; SM75 refuses and names the reason; the test
backend needs the explicit flag), missing kernels on a proven device is
explicit, the test backend is deterministic across runs and counts nodes/ops,
it refuses the bit-exactness gate, `compare_with_reference` is bit-exact (no
tolerance), load/prepack ordering, typed refusal for a malformed graph, the
OOM/device/unsupported exception mapping, error counters, and a real
wall-clock measurement on a 5000-node workload.

## 4. Definition of Done status

```text
explicit failure modes for OOM / CUDA / unsupported        DONE (typed + tested)
no float path, no approximation, no silent fallback        DONE (by construction + tests)
worker executes the frozen block bit-exactly               BLOCKED — needs SM86/SM89
                                                           hardware and GPU_REAL_SMOKE
```

The blocked half is a hardware dependency, not an unknown: the loader,
selection and gate code are in place; on a proven host the remaining work is
running the frozen vector/operator gates and the 310-node block self-check.

## 5. Carried into B2-07 and later

1. B2-07 builds the commit pipeline on top of `execute()`; its roots come from
   the same canonical encoder that `graphid.py` already mirrors, and its
   final acceptance gate is the same GPU_REAL_SMOKE.
2. The release image must ship the frozen kernel sources
   (`gpu/f5b1`, `gpu/f5b2`) and the CUDA torch build — B7 packaging, and the
   reason `FusedMMA13W10Backend.load` refuses when they are missing.
3. A device-error reset policy (retry once, then fail the task and keep the
   worker alive) belongs with the B2-09 recovery work, which consumes the
   `DeviceError`/`OutOfMemoryError` types defined here.
