## 1. Protocol implemented (from the frozen reference)

`deploy/da_replica.py` is the DA_REPLICA_V1 reference provider:

```text
GET  /health   provider info + advertised Ed25519 key
POST /store    the provider recomputes output_root from the bytes it received
               BEFORE storing; a mismatch is refused with a reason
POST /attest   the canonical signed DAAttestation (only after a verified store)
```

The attestation is signed over
`PRISMA_GEMM_SIG_V1\x00 || encode_canonical(attestation with signature cleared)`
and travels in the Go-shaped base64 wire form; the chain verifies the same
preimage (`canonical.VerifyGraphDAAttestationV2Signature`) and finalizes only
with exactly two attesters (`keeper.go`). Providers submit their own
attestation transactions — the worker's job is to get the bundle in and
observe the quorum.

## 2. What the worker enforces

- **Upload is not storage.** A provider counts only when its attestation
  verifies here: protocol version, task, assignment, output root, output
  bytes, retention window, advertised provider key, and the Ed25519 signature
  over the frozen preimage.
- **The quorum is never bypassed.** `ensure_quorum` raises
  `QuorumNotReached` (carrying every provider's outcome) unless the configured
  number of *verified* attestations exists. It never degrades to
  "uploaded somewhere".
- **Bounded by construction**: per-provider HTTP timeouts, bounded retries
  with linear backoff, and no unbounded loop.
- **Provider refusals keep their reason**: HTTP error bodies are decoded so a
  provider's `OUTPUT_ROOT_MISMATCH`-style message reaches the operator
  instead of being flattened into "HTTP Error 400" (a real bug found by the
  tests).

## 3. Evidence

`pytest -q worker/tests` — **112 passed, 1 skipped** (11 new). The DA tests run
**real HTTP servers** with **real Ed25519 keys** and build the attestation
preimage with the frozen encoder
(`compute/canonical/python/canonical_ref.py`), so the verification path is
checked against the authoritative implementation, not a mirror:

```text
3/3 providers verify -> quorum 3
1/3 provider offline -> 2 verified, quorum reached (outcome records the failure)
2/3 providers offline -> QuorumNotReached with all three outcomes
upload ok + attest fails -> the provider does NOT count (upload is not storage)
bad signature / wrong output root / stale protocol version -> refused
transient failure -> retried with backoff, then verified (attest_calls == 2)
provider with no advertised key -> refused
quorum > provider count / quorum 0 -> explicit configuration errors
store refusal -> the provider's own reason survives ("store refused: …")
```
