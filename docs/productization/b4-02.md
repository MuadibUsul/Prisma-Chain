# B4-02 — DA storage engine

```text
Task ID     B4-02
Status      DONE (2026-10-05; the optional object-store interface is deliberately not built)
Branch      product/testnet-alpha
Module      da/prisma_da/storage.py, da/prisma_da/policy.py
Goal        durable, verifiable artifact storage
```

## 1. What is enforced

```text
artifact index        in-memory index rebuilt from disk at start-up (rescan);
                      per-task entry: bytes, output_root, content sha256, timestamps,
                      m/n, task_id32, assignment_id; the on-disk layout is the
                      Phase E one (compatible with existing devnet data dirs)
content hash          sha256 recorded on write, re-verified on EVERY read
atomic write          staged in .incoming, fsynced, renamed; never half artifacts
NVMe backend          the default local-filesystem backend (the only one built)
quota                 per-provider cap with an explicit rejection: HTTP 413 and a
                      QuotaExceeded error; no implicit eviction
TTL                   retention per artifact class (default class "output"); 0 = keep
                      forever, so a misconfigured policy cannot delete everything
garbage collection    deletable only when TTL expired AND no live challenge
                      references the task; --dry-run supported; every deletion logged
integrity scan        full re-hash of every indexed artifact; mismatch -> quarantine
                      (moved aside with a reason) and removed from the serving set;
                      `prisma-da scan` on demand and an optional periodic scan
typed chunk proof     GET /v1/da/{task}/tile/{i}/{j}: the frozen 8x8-tile leaf and
                      Merkle proof, verified by merkle_proofs.verify_inclusion
object store          NOT built (roadmap marks it optional): the storage layer's
                      semantics are the contract a future backend must satisfy
```

## 2. Evidence

`pytest -q da/tests` — **21 passed** (9 new for B4-02):

```text
quota: rejects before writing, accepts an exactly-fitting upload, unlimited when 0
gc: never deletes without a TTL; respects live challenges; dry run deletes nothing;
    deletes an expired artifact and reports freed bytes; keeps fresh artifacts;
    per-class TTL overrides the default
integrity scan: healthy scan reports 1/1; a corrupted blob is quarantined and the
    artifact disappears from the serving set
typed chunk proof: verifies with the frozen verify_inclusion; 8x8 int32 tile size;
    out-of-range and malformed coordinates answer 404/400
daemon: an upload over the cap answers 413 with the reason and is counted
```

One test-side bug was found and fixed while writing them (a dataclass field was
captured by reference, so the mutated timestamp also became the "now"
baseline) — the implementation was correct, the assertion was not.

## 3. Definition of Done check

```text
every served byte verifies against its content hash    yes — read path + periodic scan
crash during write never leaves a served corrupt artifact   yes — stage+fsync+rename
GC can never delete a challenge-relevant artifact       yes — live-challenge argument
                                                        is mandatory to bypass nothing:
                                                        it only ever *protects* tasks
```

## 4. Carried into B4-03 / later

- B4-03 (challenge responder) supplies the live-challenge set from the chain and
  wires `MsgRespondGraphDAChallenge` with the tile proof produced here.
- An S3-compatible backend stays unbuilt on purpose; if it is added, it must
  satisfy the same verify-on-write/verify-on-read semantics (recorded here so
  the requirement cannot be lost).
