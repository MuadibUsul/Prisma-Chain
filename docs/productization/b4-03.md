## 1. What is enforced

```text
chain challenge subscription  the frozen chain exposes per-task queries (no per-provider
                              challenge list), so the adapter scans tasks with an explicit
                              bound and reads the DA section defensively (open status +
                              deadline); `prisma-da responder` polls on an interval
proof lookup                  the artifact is located in the local store; a corrupted
                              artifact is quarantined and reported, never proven for
typed chunk proof             storage.tile() — the frozen 8x8 leaf + Merkle proof that
                              verifies with merkle_proofs.verify_inclusion; the exact
                              verified payload is what the transaction carries
deadline scheduler            chain-height based, with a safety margin: a challenge whose
                              deadline is inside the margin is NOT started (no half answer)
response tx                   `tx compute respond-graph-da-challenge --challenge-id …
                              --chunk … --chunk-index/--chunk-count --chunk-proof …`
                              signed from the temporary 0700 provider keyring
after-loss detection          artifact gone or unverifiable -> an objective record
                              (task, challenge, reason) in `losses`; nothing is fabricated
                              to dodge the chain's penalty path
metrics                       discovered / answered / too_late / lost / failed and response
                              latency (last/avg/max)
GC link                       `live_challenges()` feeds `prisma-da gc`, so a challenged
                              artifact can never be deleted while the challenge is open
```

## 2. Evidence

`pytest -q da/tests` — **30 passed** (9 new):

```text
answers a challenge in time and the submitted tile verifies with the frozen verifier
a deadline inside the safety margin is not answered (metrics.too_late, no tx)
a missing artifact is reported objectively (losses recorded, no tx)
a corrupted artifact is quarantined and reported as a loss (no tx)
discovery failure and response-transaction failure are counted, never fatal
the scheduler runs bounded iterations (max_iterations + injected sleep)
live_challenges() protects the artifact from GC (TTL expired, still kept)
the adapter extracts a challenge from a task document and ignores non-open ones
the response transaction carries the documented flags (chunk, index, count, proofs)
```

## 3. Definition of Done check

```text
challenges are answered with verifiable proofs before deadlines   yes — height-based
     scheduler with a safety margin; the proof is the frozen one, verified in tests
after-loss is reported honestly                                    yes — objective loss
     records, no fabricated proof, the chain's penalty path applies untouched
```
