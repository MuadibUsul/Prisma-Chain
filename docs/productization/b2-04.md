# B2-04 — Worker job fetch / accept

```text

Status      DONE (2026-10-05)

Goal        discover compatible jobs, accept atomically, survive restarts
```

## 1. Design

```text
discovery        chain task scan (query compute task --task-id N) from a bounded
                 start id, stopping after a run of misses — the B6 job API does
                 not exist yet, and the scan bound is explicit, never unbounded
compatibility    hard filter on model id / mode / spec version and task status;
                 anything else is refused (forbidden to accept mismatches)
accept           one accept-task transaction, signed from the temporary keyring
assignment ref   the accepted task's chain state is re-read after the tx and the
                 worker must be the assignee before success is reported
journal          write-ahead, one atomically written + fsynced JSON file per task;
                 phases discovered -> accepting -> accepted | accept_failed ->
                 executing -> submitted -> terminal, with a bounded history
timeout          a task whose deadline is within the safety margin is refused
                 before any transaction
duplicates       journal-first idempotency: an already accepted task is reported
                 as-is without touching the chain; a crash mid-accept leaves
                 `accepting`, which the next run reconciles against the chain
                 (never guessed)
```

## 3. Bugs the live runs found (all fixed and pinned by tests)

1. **`QueryTaskResponse` is a base64 `task_json` blob**, not a flat object —
   the mocked unit tests hid this, live discovery found it. `chain.py` now
   decodes the envelope (`decode_blob`, also used for `model_json` in B2-05)
   and tolerates a future flat shape.
2. **The smoke's `tx()` helper did not check the DeliverTx code** — a failed
   registration looked like a success and the task simply never existed.
   It now raises with the chain's own log line.
3. **`jobs accept` was missing `--keystore`/`--passphrase-stdin`**, so the CLI
   aborted with an argparse error instead of accepting.
4. **Duplicate accept semantics**: the status filter refused a re-accept
   before the journal idempotency could answer; the CLI now reports the
   existing journal entry and exits 0 without touching the chain.

## 4. Definition of Done check

```text
accepts only compatible jobs          yes — hard filter, live-refused case
every accept journaled before side effects   yes — `accepting` written and
                                      fsynced before the transaction

                                      idempotency + crash reconciliation, live case
```

   source behind the same compatibility filter.

   already the single state machine those tasks must extend.
3. The verifiable-mode model registration needs the frozen VM program

   focused on the accept mechanics.
