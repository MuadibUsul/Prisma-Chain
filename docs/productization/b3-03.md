## 1. What is persisted and recovered

```text
persisted   per-dispute journal: phase (open/trail/midpoint/wide/arb_ready/resolved),
            bond, txhash, transcript digest, locked roots, midpoint history, deadlines,
            last observed chain state; atomic writes (tmp + rename) with bounded history
restart     re-read every ACTIVE dispute, re-derive the chain's dispute state through
            DisputeOps, and act on what the chain says: resolved -> record the outcome;
            still running -> keep it active with the chain state (optionally handed to
            the driver for the next step). The chain is the source of truth; the ledger
            only prevents forgetting.
duplicate   opening a second challenge for an active dispute is refused
idempotence recovery can run twice harmlessly
```

`pytest -q watcher/tests` — **31 passed** (6 new):

    roots and midpoint history intact, and recovery resumes it — the product-code
    mirror of the F.5C A6-09 requirement
