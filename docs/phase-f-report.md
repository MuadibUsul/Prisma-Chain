# Phase F report: verifiable Transformer block

Branch `protocol/transformer-phase-f` (worktree from
`origin/protocol/gemm-phase-e-permissionless` @ 6d6d709). Everything below
is measured in this worktree; PASS / FAIL / NOT TESTED are kept distinct
and nothing is claimed beyond its test scope.

## What was built

* **CanonicalMathV1** (Q12.20, ties-to-even, saturating, pinned constants,
  zero libm) selected by a reproducible numeric-design analysis, with
  predeclared acceptance thresholds (docs/canonical-math-v1.md,
  docs/canonical-math-v1-analysis.json).
* **Canonical operator framework** (`compute/canonical/`): static
  registry, descriptor-bound tensor commitments (64-element chunk Merkle,
  zero padding, self-pairing), seven frozen operators plus the GEMM
  adapter (frozen v0.1.1 arithmetic, optional transpose-B), all with a
  Python mirror and cross-language bit-exact vectors.
* **CANONICAL_GRAPH_V1**: static hashable DAGs, on-demand state trail
  bisection to the first divergent node, per-operator bounded arbitration,
  GDS1 persisted disputes, GraphResultCommit, VerifiedGraphWorkReceiptV1,
  descriptor-derived work counters (no universal CWU).
* **TRANSFORMER_BLOCK_V1**: attention and SwiGLU as graph macros with
  converter-pre-sliced per-head weights, head concatenation by linearity,
  folded attention scale, static W8A8 quantization (mini: 90 nodes,
  2.69M GEMM MACs; medium: 166 nodes, 272.6M GEMM MACs).
* **Chain settlement** (`chain/x/compute/graph*.go`, eight new messages,
  GraphGasV1): escrow/bond/window/arbitration/settlement reusing the
  Phase D/E mechanics in an independent namespace; the bounded-VM,
  lightweight and frozen GEMM paths are untouched.
* **Four-validator devnet E2E** (`deploy/multivalidator/f_graph_test.py`)
  driving real transactions with the Python canonical mirror:
  honest / fraud / false-challenge scenarios.

## Final report questions

**Q1. Do all operators agree byte for byte between the Go and Python
implementations?** YES for the covered surface: the committed
`canonical_vectors.json` (generated by the Python mirror) is replayed by
`TestCanonicalCrossLanguageVectors` and includes math primitives
(including the pinned invsqrt table regeneration, exp split, sigmoid,
softmax division), tensor roots, eleven operator vectors
(ADD/MUL/REQUANTIZE fx+int8/RMSNORM/ROPE/SILU/SOFTMAX/GEMM plain+transpose)
and a full ten-node graph whose `GraphID`, state trail, output roots and
work vector are identical on both sides. The Python self-test
independently regenerates the pinned constants and the vector file.

**Q2. Is the Q-format choice justified and are the accuracy thresholds
predeclared?** YES for the numeric design: Q16.16/Q12.20/Q8.24 were
simulated against float64 on fixed seeds plus adversarial vectors
(docs/canonical-math-v1-analysis.json); Q12.20 was chosen; Q8.24 was
excluded for dynamic range (softmax cosine 0.30). Thresholds were frozen
in docs/canonical-math-v1.md before any benchmark. The end-to-end
block-vs-float accuracy gate with a real model belongs to the converter
milestone and is NOT TESTED (see Q7).

**Q3. Does a graph dispute localize to the first divergent node and
arbitrate boundedly per operator?** YES. Unit tests cover fraud injection
at EVERY node position of the mini block (localization exact for all
positions) and per-operator arbitration verdicts in both directions,
including row operators with rows shorter than one chunk. On the devnet,
a corrupted ADD output of the 90-node block localized to node 89 in seven
bisection rounds and a permissionless arbitration transaction
(1.38M gas) ended `challenger_wins`.

**Q4. Does the chain integration reuse the Phase D/E mechanisms without
touching the old paths?** YES within the tested scope: independent storage
namespace/statuses; reuse of escrow, worker-bond reservation, challenge
window, one-active-challenge DoS bound, feeSplit (burn 20% / monitors 5%),
bond burning, worker slashing and receipt settlement; midpoints clocked
by block height. The bounded-VM, lightweight and GEMM suites remain green
(38 tests), and the frozen GEMM ProtocolVersion is unchanged. Graph tasks
do not yet reuse the DA attestation quorum (DA remains available as-is for
graph inputs/outputs; no per-operator DA exists) — documented limit.

**Q5. Did the four-validator devnet E2E pass and converge?** YES
(docs/phase-f-e2e-results.json): honest flow finalized with receipt
(early finalize refused); fraud flow ended `fraud` with no receipt, the
challenger's balance matching the expected accounting exactly
(5.5M = 10M − 5M locked worker bond − 1M challenge bond + 1M refund +
0.5M slash) and the worker slashed; false challenge refused at admission;
all four validators converged on one app hash. Measured gas per message
in docs/phase-f-gas-results.json (post 4.52M / accept 1.28M / submit
1.39M / challenge 1.32M / claim 0.23-0.27M / midpoint 0.26M / arbitrate
1.38M / finalize 1.38M, GraphGasV1).

**Q6. Can a worker bias its own work counters or forge a receipt?** NO
within the protocol: the settlement work vector is derived from the
static descriptor (`GraphWorkVector`) and a test proves it equals the
executed vector for both block sizes; the receipt is derived by the chain
from the validated signed commitment and re-verifies every output root;
the result commitment is domain-separated, zeroes its signature field for
the preimage, and is double-bound (tx sender = on-chain party = bonded
network key).

**Q7. Real pinned model block and GPU backend?** NOT TESTED.
`REAL_MODEL_BLOCK = NOT TESTED` (no converter run, no pinned model
revision converted) and `GPU_BACKEND = NOT TESTED` (no GPU operator
implementation exists). By the predeclared rule the phase status is
PARTIAL: the protocol layer (canonical math/operators/graph/chain) is
PASS at its tested scope; model relevance is not yet demonstrated on a
real checkpoint. docs/transformer-block-v1.md records the conversion plan.

**Q8. Watcher and DA reuse for graphs?** PARTIAL/NOT TESTED. The Phase E
DA_REPLICA_V1 machinery is unchanged and continues to serve GEMM inputs
and outputs; graph inputs/weights/outputs are ordinary committed tensors
and can be stored by the same providers, but no graph-specific watcher
fast-verification run was performed (the Phase E watcher path covers
GEMM). A block-level watcher E2E is NOT TESTED.

## Failure log (honest record)

* The softmax/RMSNorm arbiters initially handled only chunks inside row 0;
  the block's score rows are shorter than one chunk, so arbitration would
  have returned BothInvalid for later rows. Fixed with explicit
  row-span geometry and strict evidence coverage.
* The ExpFx doc comment claimed floor division while Go (and now every
  backend) truncates toward zero; semantics frozen as truncation with
  |f| < ln2 and documented in both languages.
* Midpoint epochs cannot require exact-height equality under mempool
  timing; the chain now bounds the clock instead, with the round window
  enforced by the canonical layer.
* Windows command lengths cannot carry a 54KB descriptor hex; the E2E
  sends argument files through the container with `jq | xargs`.
