## 摘要

Prisma 的长期目的，是把由不同个人和机构拥有、当前未被充分使用的算力组织成开放的 AI 计算网络，让开发者和用户在少数大型商业平台之外拥有可调用、可验证、可迁移的选择。网络以公开协议、可独立部署的软件和许可明确的模型为基础；计算参与者按设备能力承接适合的任务。能否在价格、完成率和使用体验上形成真正有竞争力的服务，必须由公开实测证明。

Prisma Chain 拟建立一条独立的 PoS/BFT 应用链，让用户发布 AI 任务、托管费用，让提供算力的工作者领取有条件的报酬。**共识验证者负责出块和确定性状态转换；AI 计算由链外工作者执行，不参与出块，也不以 GPU 耗电量决定共识安全。**因此，本文把“有用工作”定义为受任务协议计费和约束的服务，而不是替代 PoS 的工作量证明。

任务沿用 v0.1 提出的两条验收路径。**可验证模式**只接收公开输入和有界、确定性的整数程序：协议要求独立监控者完整复算，错误结果可以进入交互式挑战，由链上裁决一个步骤。**轻量模式**面向 Qwen3-14B、Qwen3-32B 推理及将来的公共模型微调：它依赖签名交付记录、可复测的服务指标、抽样评估与声誉，不声称对自然语言回答提供逐步欺诈证明，也不以主观质量直接触发链上罚没。

截至本版，本地开发网已实际完成单验证者出块、签名转账，以及公开整数任务从托管到结算的链上闭环。错误结果、虚假挑战和超时处理有模块测试。轻量模式已用合成任务验收双签收据、按输出 token 计费、退款和分账；本地 API 还验证了固定哈希分词器的独立计量、接单后的失败重试及链上结算状态查询。集成脚本已通过工作者持有的测试网 CLI 签名账户自动提交双签收据；运行中的 Compose 工作者尚未配置链签名服务，监控确认与最终结算仍由脚本执行。签名算力网关仍只用确定性模拟模型交付。真实 Qwen 跨机推理、生产级 Tier 0 隐私和多运营者网络仍待完成。

## 1. 从概念到可检验的协议

分散的 GPU 可能为推理或训练提供容量，但“有算力”并不自动产生可靠服务。用户还需要固定模型版本、知道任务由谁接单、得到可复核的交付记录，并在失败时取回托管费用。工作者需要可预期的任务价格和明确的责任边界。Prisma 以任务协议连接这两侧，用链保存付款与争议所需的最小公共状态。

### 1.1 愿景与可检验的原则

AI 计算的入口、模型选择和定价不应只能由少数资金与数据中心规模占优的平台决定。Prisma 希望让闲置设备的拥有者能够提供算力，让任何符合规则的网关可以接入，让开发者通过统一 API 使用开放模型及可验证任务。协议、核心节点软件、客户端 SDK 和验收规则应在明确的开源许可证下发布，并支持第三方独立构建和部署；模型目录至少应包含一个许可允许独立获取权重并提供服务的固定版本模型。模型权重与训练数据仍须分别遵守其自身许可证。

“调动全网闲置算力”是开放参与目标，不是对每台设备都能运行每个模型的承诺。工作者按显存、计算能力、网络带宽、稳定性和所持模型进入合适的任务池；小型公开 VM 任务与大型分层推理有不同门槛。网络需要公开非创世运营者的有效任务份额、完成率、单位成本、延迟和隐私事件，才能判断资源是否真正被利用，以及是否给用户带来了可选择的服务。跨地域分层推理在延迟敏感任务上可能不如集中集群，适合的任务类型必须由基准测试决定。

### 1.2 目标用户与市场选择

原白皮书面向独立开发者、研究者、Web3 团队和中小企业，也设想多个互不信任机构共同使用中立、可验证的协作算力。首批可验证任务适合**愿意公开输入和程序**、需要第三方重算及公开争议路径的用户；轻量模式在真实模型交付和计费验收完成后，才面向普通大模型请求。涉及商业秘密或跨机构敏感数据的场景需要更强的保密技术与运营证明，不能因为 Tier 0 的模型分层而视为已解决。拥有自建集群并要求最低延迟的用户可能更适合集中部署。

算力市场有双边冷启动问题：没有订单，工作者难以收回设备和监控成本；没有可靠工作者，用户不会持续发单。创世运营者可以提供早期可用性，但其份额与退出规则必须公开。网络需要用真实完成率、价格和争议结果验证需求，而不能用节点数或代币补贴代替付费订单。

### 1.3 为什么采用独立应用链

签名收据加普通支付服务已足以处理许多 AI 订单。Prisma 选择应用链的理由是让互不信任的参与者共用一份可审计的任务托管、保证金、挑战期限、确定性裁决和供应账本；验证者按相同规则执行，单个网关不能改写已托管任务的付款条件。独立链也带来验证者成本、跨链资产和用户进入门槛、治理复杂度及新的安全责任。因此，只有当多运营者和公开争议确有需求，且服务成本可与现有云和链外算力市场竞争时，这项架构才有实际价值。

现有相关路线包括去中心化 GPU 租赁、分布式推理框架以及以激励机制协调 AI 工作的网络。Prisma 的拟议组合是**可复算的公开任务争议、轻量大模型交付、可更换的计算组和链上托管**。各路线解决的问题不同；目前没有足够的跨机性能、成本或真实订单数据，不能据此断言 Prisma 优于任何具体服务。

与 v0.1 相比，本版作出以下约束：

| 议题 | v0.1 的概念表述 | v0.2 的协议边界 |
| --- | --- | --- |
| 共识 | 有用工作量证明取代无意义的哈希计算 | PoS/CometBFT 出块；AI 是独立的有偿任务，计算结果不决定区块有效性 |
| 欺诈证明 | 二分后只需验证约 `log₂N` 轮 | 约 `log₂N` 轮降低链上定位成本；至少一名诚实挑战者仍要完整复算，日常监控也有实际成本 |
| 大模型 | 已提出可验证与轻量两档，但未界定首版可证明工作负载和轻量验收证据 | 大模型先走轻量模式；完整逐步证明只覆盖受限、公开、确定性的工作负载 |
| 路由 | 按任务语义难度唤醒固定数量节点 | 根据模型拓扑、显存、带宽、延迟与队列实测安排副本或流水线；不预设更多节点更快 |
| 隐私 | 分片与“秘密共享”并列 | Tier 0 只承诺经过披露的相对隐私；模型分层不构成密码学秘密共享 |
| 代币 | 创世奖励池释放与新增发行的关系未定义清楚 | 创世锁定资产的释放是转账，新增发行才增加总供应；两笔账分别记录 |

系统成功的条件是可验证的服务质量和可持续成本，而不是节点数量、吞吐量或币价的宣传数值。跨机性能必须与相同 GPU 的集中部署在相同工作负载下比较。

## 2. 系统边界与参与者

Prisma 是基于 Cosmos SDK 与 CometBFT 的**独立应用链**，不是 Cosmos Hub。链上复用账户、转账、共识质押、治理和升级模块，并由 `x/compute` 保存模型、工作者保证金、任务托管、挑战和结算状态。共识状态机只执行有界、确定性的密码学及整数运算；它不调用 GPU、模型服务或外部网络。

| 参与者 | 责任 | 无法单独做到的事 |
| --- | --- | --- |
| 用户 | 固定任务模式、模型版本、输入承诺、费用和期限；托管费用 | 不能因不满意主观答案而自动没收工作者保证金 |
| 工作者 | 锁定独立保证金，执行任务并提交结果承诺 | 不能仅凭自报结果提走托管费用 |
| 监控者／挑战者 | 按协议对公开任务完整复算，提交确认或挑战 | 确认签名本身不能证明实际完成复算 |
| 网关／协调者 | 发现可用计算组、路由请求、签署交付记录 | 不能修改任务模型版本或单方放款 |
| 共识验证者 | 按 PoS/BFT 规则排序交易，执行同一链上状态机 | 不在共识过程中重跑 Qwen 或其他大模型 |

**共识质押与工作者保证金是不同的风险池。**计算错误可以影响工作者的任务保证金，但不应自动罚没无关委托人的共识质押。两个监控地址并不证明背后是两个独立运营者；独立性还需要选任、公开身份和集中度审查。

## 3. 模型登记与任务生命周期

模型以 `model_id + spec_version` 标识。登记项固定运行镜像、分词器和权重摘要；可验证模式还固定 VM 程序。更新发布新版本，已发布任务始终引用原版本。哈希证明的是版本绑定，不证明相应外部文件一直可取得，也不证明某节点实际运行了该文件。

统一任务信封包含：

| 字段 | 含义 |
| --- | --- |
| `mode` | `verifiable` 或 `lightweight` |
| `model_id`, `spec_version` | 不可覆写的模型与执行规则版本 |
| `input_commitment` | 规范化公开输入或加密私有输入的承诺 |
| `data_ref` | 取数位置；位置本身不等于可用性保证 |
| `max_fee` | 预先托管的费用上限 |
| `deadline` | 接受结果的最后链高 |
| `privacy_tier` | `public` 或 `tier0_relative` |

链上任务按**发布 → 接单 → 待确认 → 挑战 → 结算／退款**转换。提交后的输出在完成模式对应的验收前是临时结果。挑战胜负、超时和未满足确认条件分别有确定的结算或退款路径；任何地址都不能让同一任务同时付款和退款。链外重试保留同一个 `task_id`，更换执行尝试编号与租约版本；当前链模块按任务 ID 防止再次结算，并未把每个链外尝试编号写入共识状态。

本地开发网的可验证任务要求工作者按费用额度预留保证金，至少两名不同且已质押的监控地址确认，挑战期结束后才可结算。链只检查质押、地址差异与确认交易，**不能从签名证明监控者真的复算了程序**；当前也没有持续运行的自动监控服务。两个地址可以同属一人，因此这不是对抗串谋的充分条件。对轻量任务，当前代码**关闭自动结算并保留超时退款**，直到签名收据、可信 token 计量和定价规则接入链上付款判断。

## 4. 可验证模式：受限 VM 与交互式挑战

完整欺诈证明要求被争议的一步具有相同的输入、数值语义和结果。首版 `prismavm` 是直线执行的整数虚拟机：16 个寄存器、最多 64 个输入值、最多 4096 条指令；没有跳转、浮点、时钟、文件或网络调用。指令、溢出、除法截断和承诺编码由版本化规范确定。这足以支持经过编译的有界分类等公开任务，**不是通用 14B/32B 大模型的证明系统**。

可验证模型程序与规范化输入在挑战期内对任何人可取得。当前实现把程序和公开输入写入链状态；若未来改用外部数据可用性层，必须先证明挑战者能在时限内获取必要字节，否则不得因“无人挑战”放款。仅登记权重哈希、提交 Merkle 根或宣称有人抽查，都不足以证明计算正确。

工作者提交输出摘要、执行轨迹根和端点证明。监控者需要独立从第一步算到最后一步，比较结果与承诺；发现分歧时提交自己的端点主张并锁定挑战押金。**任何非该任务工作者的地址**都可以在挑战期内缴纳押金发起挑战，无须先成为指定监控者。双方在有期限的轮次中提交中点状态及 Merkle 证明，争议区间逐次减半。最后由全体验证者执行同一个有界步骤。对于 `N` 步轨迹，二分定位约需 `⌈log₂N⌉` 轮，但监控者的完整复算成本仍约随 `N` 增长。有人愿意获取公开数据、复算并及时挑战，是乐观结算的安全前提。

错误结果、无效证明、虚假挑战、拒绝响应及双方均未有效响应有不同的押金去向。当前测试网规则在工作者胜诉时销毁失败挑战者的押金并重新开放完整挑战窗口，以免工作者用自控挑战者无成本地反复抢占。失败任务的用户费用应退回；成功但被恶意挑战的工作者不应失去报酬；重复结算必须拒绝。当前 VM 和 `x/compute` 对这些路径有自动化测试，本地链已实际验收一次**无人发起挑战的正确结果结算**。单场争议仍独占挑战入口，开放多挑战者规则、恶意挑战和数据扣留演练仍是上线门槛。

## 5. 轻量模式：大模型推理与公共微调

轻量模式的首批目标负载是固定版本的 Qwen3-14B、Qwen3-32B 推理和公共模型微调。模型权重、分词器、运行镜像与推理参数要固定摘要；不同版本形成不同任务。工作者与网关分别签署带任务 ID、尝试编号、模型版本、输出承诺、交付状态和计量值的记录。当前推理费率以**交付文本**经固定 `tokenizer.json` 编码且不额外添加特殊 token 的数量为准；工作者与网关各自复核，不能照收模型服务自报的生成 token 数。未交付的隐藏推理内容不计入此费率。

大模型答案的正确性往往是主观的，跨硬件浮点运行也未满足首版 VM 的逐位一致条件。因此，随机复跑、隐藏测试、用户反馈和独立质量评估用于调整声誉和接单资格；它们不自动把“不够好”的回答判定为可链上罚没的欺诈。签名收据证明谁声称交付了什么，不证明回答真实、优质或由指定权重完整生成。

公共微调任务的目标验收是：固定基础模型、训练数据版本和训练配置；工作者提交权重增量；独立评估器用保留集测试并抽查训练记录。通过评估才释放基础奖励。评估设计、数据许可、抗过拟合与串谋处理均需另行完成。**截至本版，链上轻量付款只通过合成收据的本地测试；真实模型交付计量与公共微调奖励池尚未上线。**

## 6. 算力网络与故障恢复

对同一请求的真正跨机模型并行，与在多机上各跑一份完整模型处理不同请求，是两种不同服务。前者受层间激活传输和网络延迟约束；后者通常提升吞吐量。测试网计划以 Qwen3-14B 的双机流水线和 Qwen3-32B 的四阶段实验组验证前者，并保留完整模型副本承接独立请求。阶段数由模型分层、显存、带宽与实测服务指标决定，不能从“问题难度”直接推导。真正的 MoE 模型另按专家通信和路由成本调度。

节点签名公告支持的模型版本、容量与短期租约。当前本地路由按独立探针测得的延迟、估算带宽和队列深度排序；公告中的显存尚未参与准入，真实请求指标也尚未反馈到调度。目标网络需补齐显存准入、真实服务指标和接单前的协调权移交。当前租约实现只允许旧租约到期后由新协调者取得更高版本，工作者会拒绝旧版本请求；多主机共享租约与接单后的主动接管尚未完成。未来的 GPU KV 状态不会因为路由权迁移而自动搬家，需要热备和检查点；无法恢复时按同一任务 ID 重试，链上仍最多付款一次。

当前本地网络已有 Ed25519 签名公告、测量路由、SQLite 租约版本、防旧协调者重放、工作者与网关双重签名及幂等收据。它使用**单阶段 CPU 模拟模型**。多主机共享租约、GPU KV 检查点、真实 Qwen 跨机服务和与集中部署的性能对照均未验收；仓库中的 Ray/vLLM 启动文件只是部署实验模板。

长期接入目标是让不同运营者的合格设备按公开规则加入相应任务池。节点软件须验证模型和运行文件、声明并接受实测的能力准入；计算与网络条件不够的设备只承接适合的任务。当前节点仍需预置可信公钥、允许的主机及链账户绑定，尚无无需项目方操作的开放接入；显存也只在公告中声明，尚未进入路由准入。上线前需评估冒名、女巫账户、虚报容量和运营者集中控制。

### 6.1 最终对外形态：统一 Prisma API

最终交付给开发者的是**一个有版本规范的 API 与 SDK**。开发者提交模型、模式、输入、费用上限和隐私等级；网关在内部完成模型版本校验、节点选择、跨机执行、故障重试、交付计量以及链上任务状态同步。多个运营者应能运行兼容网关，避免对外接口被单一入口独占；网关的路由权不包含单方结算或改写链上任务的权力。

API 至少覆盖两类调用：推理请求支持流式输出并返回固定模型版本、`task_id`、用量和双方签名收据；可验证计算与微调使用异步任务接口，支持提交、查询结果及按模式适用的挑战、评估、结算或退款状态。执行前给出费用报价和上限。同步返回的回答标记为**已交付的临时结果**；挑战期或轻量验收完成后，再提供可独立查询的最终状态。客户端重试沿用同一任务 ID 和幂等键；断流后仍可查询任务状态与签名收据，若要重放输出，必须设计限时加密保存或客户端检查点及删除规则。重试不能产生第二次付款。普通开发者可使用受管理的 API 凭据与预付余额；希望直接控制资金的用户可通过 SDK 签署链上任务，两者的托管关系必须分别披露。

完整验收要求外部客户端只凭公开 API／SDK 文档，在多运营者网络上完成真实 Qwen 推理和公开可验证任务，取得可验证的收据、费用明细及最终状态，无须手工操作内部调度器或链命令。当前本地网关已有测试性 `POST /v1/inference` 和收据查询，但调用方须提供任务信封；无资金开发模式不核验链上接单或托管，使用模拟模型及单一开发用 API 凭据。统一生产 API、流式交付、链上任务代办及托管或自持资金路径均未交付。

## 7. 数据可用性与隐私等级

可验证模式以公开程序和公开输入换取任何人可复算。用户不应把秘密数据放入该模式。轻量模式的 `tier0_relative` 目标是在入口、存储和工作组通信中采用认证与加密，并使模型层和中间表示分布于不同工作者。链只保存承诺、状态和结算资料；私有原文不应写链。

**Tier 0 是相对隐私，不是密码学秘密共享。**入口可能看到完整输入，出口可能看到完整输出；参与者串谋、中间表示反推、日志泄漏和模型权重接触仍有风险。分层部署不保证任何单个运营者永远看不到敏感数据。界面和 SDK 必须显示这一边界；当用户要求强保密保证时，不应接收任务并暗示 Tier 0 已满足要求。

本地 Compose 为开发便利使用回环 HTTP，网关 SQLite 也不提供生产级静态加密。它只运行无敏感内容的模拟任务，**不能当作已经交付了 Tier 0 加密部署**。TLS/mTLS、加密对象存储、密钥轮换、最小化日志和运营者数据处理制度是后续部署要求。TEE、ZKML、FHE 等 Tier 1 方案属于独立研发路线；本版不承诺其性能、保密强度或交付日期。

## 8. $PRSM、托管与供应账本

$PRSM 是 Prisma 链的原生记账单位，`uprsm` 是当前实现的百万分之一单位。计划用途包括 gas、任务托管、共识质押、工作者保证金及治理。**本地测试币可从开发水龙头领取，没有真实货币价值；本文不推断市场价格、流动性或收益率。**

当前可验证外部任务成功结算时，以全部托管的 `max_fee = F` 作为费用，按最小单位 `uprsm` 计算：销毁额 `B = ⌊F/5⌋`，两名确认监控者各得 `M = ⌊F/20⌋`，工作者得 `W = F − B − 2M`。整数余数进入工作者份额；当前还没有按实际 GPU 用量扣费的费率。失败或未能确认的任务走规定的退款路径，挑战押金与工作者保证金另记。监控者完整复算有真实成本，合计约 10% 的监控预算是否足够，需要在不同费用、任务长度与订单量下测量，不能由比例本身推出安全性。

总供应的守恒式是：

```text
期末供应量 = 期初供应量 + 新增发行 − 实际销毁
```

创世时已计入总供应的锁定奖励池，日后解锁只改变持有人或可流通量，**不再计作新增发行**。基础任务若使用新发行，必须单独记录铸币与对应工作；若使用锁定池，则记录池余额减少。任何新增发行、奖励池释放、gas 分配及销毁都要能由账本重算。

v0.1 的 **10 亿 $PRSM 创世量**、40% 节点奖励池、20% 生态社区、15% 团队顾问、15% 早期投资人、10% 基金会，以及年发行约创世量 5%、约两年减半的设想，仍只是经济压力测试输入，**不是已冻结的主网创世配置**。原文还建议团队顾问份额设置 1 年悬崖期及 3 年线性解锁，早期投资人份额设置锁定和线性解锁；这些也未写入本地创世规则。仓库模拟器另为尾部发行设置了 0.5% 的示例值；这也不是治理决定。必须先模拟低订单量、节点抛售、监控不足和串谋，再审查法律与运营可行性。

当前本地创世供应是 **100,000 $PRSM**，与上述 10 亿示例不同；SDK 默认通胀已在本地创世配置中置零，因为基础任务发行账本尚未实现。一次真实的 1 $PRSM 可验证任务结算，已在本地链上核对：0.2 销毁、0.7 给工作者、两名监控者各 0.05，重复结算被拒绝。该账目测试不能证明代币经济可持续。质押也不保证收益，更不能自动解决任何地区的法律分类问题。

## 9. 治理与渐进式去中心化

早期创世运营者可以提供服务兜底，但其身份、任务份额、共识投票权、奖励份额和变动规则必须公开。链上可以限制**已知**创世账户，无法单靠地址判断某运营者是否控制隐藏账户。因此还需要运营者披露、链上集中度分析和外部监督，不能用“智能合约已写死上限”代替实际去中心化证据。

标准治理模块已进入本地链；计算模块费率、挑战窗口、发行、国库和运营者上限尚未交由完整的链上参数治理。未来关键升级需要可审查的提案、延迟执行、迁移测试与紧急响应机制。紧急暂停应仅阻止新任务，已托管任务仍保留可执行的结算或退款路径；此功能当前尚未实现。

开放完整测试网的门槛是至少七个由不同运营者运行的验证节点，公布投票权与任务分配集中度，并演练节点故障、网络分区和治理升级。七个节点本身也不能证明运营者独立；应持续披露实际控制关系和部署分布。

## 11. 路线图与开放门槛

1. **本地开发网（已交付基础版）：**固定任务信封与模型版本，运行单验证者链、整数 VM、挑战测试、模拟网关和部署脚本。继续补齐真实链上挑战的自动化回归及独立监控进程。
2. **多运营者公开可验证测试网：**建设外部程序和输入可用性机制、监控者选任及运营工具；发布核心软件的明确许可证、可复现构建与节点接入规则。用恶意工作者、恶意监控者、数据扣留、拒绝响应、分区和升级测试验证结算与退款。独立审计后再考虑无许可接单。
3. **真实跨机推理：**在至少两台独立 GPU 主机上运行固定 Qwen3-14B 单请求分层推理；Qwen3-32B 四阶段为后续实验。公布首 token 延迟、每 token 延迟、吞吐量、完成率、每请求成本及与相同 GPU 集中部署的比较，不预设蜂群更快。
4. **轻量付款、公共微调与 Tier 0 部署：**先完成链上签名收据验证、固定分词器独立计量、费率与争议规则，再开放轻量付款；公共微调需独立评估。补齐传输和静态加密、密钥管理、共享租约与阶段恢复，再进行隐私和故障演练。
5. **完整测试网评估：**至少七个独立运营验证节点、治理与创世份额递减、公开供应账本、对抗测试和独立审计均通过后，才判断能否开放完整测试网。持续公布非创世工作者完成任务的份额、各类硬件的有效供给、完成率、延迟、每请求成本、隐私事件及与相同硬件集中部署的对照，以检验“闲置算力汇聚”是否产生真实价值。主网和 Tier 1 各需新的安全及法律评估。

按从零建设完整测试网的范围估计，协议、分布式系统、推理、密码学、安全和运维合计约需 **15–25 人、18–30 个月**；GPU、审计和生态冷启动另计。这是资源规划区间，不是承诺日期，也不把现有本地原型当成已完成的全部工作。

## 12. 关键风险与研究问题

**验证安全：**至少一个能取得公开数据、愿意付复算成本且能在挑战期内发交易的诚实参与者，是乐观结算的重要前提。不同质押地址可能串谋；随机轮换、监控补贴与持续可用性仍未完成。工作者网络公钥登记现要求对链 ID、账户和公钥的密钥持有签名；未证明的旧登记不能参与轻量任务。开放付费接单前仍需密钥轮换规则及已有账户的升级安排。

**性能与活性：**跨机传输可能比集中部署更慢；入口、协调者、阶段工作者或外部数据源掉线都可导致超时。共享租约、检查点和重试只能降低损失，不能保证无中断；必须报告失败率和用户退款时间。

**供给与开放：**闲置设备的在线时段、带宽与显存差异很大，供给可能在高需求时下降；公开招募节点本身不保证有效容量。仓库公开可读与正式授予源码复用权限是不同进度，核心软件的许可证和独立部署能力需在开放交付时明确。开放模型权重、训练数据和第三方依赖也须分别审查许可。

**隐私与模型资产：**Tier 0 的入口、出口和中间表示泄露面无法靠模型分层消除。公共模型任务不能外推到私有模型保护；Tier 1 需要独立威胁模型与实现证据。

**经济与治理：**测试币不提供真实的作恶成本证据。代币价格、订单量、监控成本和 GPU 供给可能同时恶化。项目方隐藏账户、监控者串谋、投票权集中和紧急权限滥用无法由单一合约规则完全解决。

**法律与数据责任：**代币、质押报酬、用户数据、模型权重和训练集涉及不同辖区的要求。任何“功能型代币”或“主动工作报酬”的命名都不自动确定法律属性。公开服务前需按实际销售、运营和数据流向取得当地专业审查。
